# 0020: Reconcile interrupted Content continuations through recorded ancestry

Date: October 31, 2026. Status: **Implementation record; owner acceptance pending**.

Extend ADR 0019's explicit continuation with read-only reconciliation of an interrupted
resumed EXECUTE attempt. Earlier ADR acceptance statuses and migrations remain unchanged.
This record does not authorize worker activation.

Use the existing C3c installation guard, operator confirmation, occupied ownership transfer,
fresh epoch and fenced D5b-1 terminal transaction. Resolve inherited stages through the exact
claimed RESUME audit plan, applied control, successful original reconciliation and retained
qualification packet. Revalidate the original private inventory, recovery observation,
resume-verifier completion seals, runtime bindings and linked checkpoint. Include recorded
ancestor/verifier children and previously reviewed descendants in the operator's review.
Live or unobservable identities veto recovery; negative process observations alone grant no authority.

Create an in-memory projection of the permitted original prefix and actual new stages for
the native recovery readers. Each inherited command retains its original attempt and epoch.
Never create copied stage rows. Reopen native Bronze, Silver, Gold, reference and Content
using the existing independent adapters; perform external work outside transactions.
The terminal transaction registers the exact verified result/dependencies, applies the current
RECONCILE, appends audit evidence and releases ownership together. Preserve interrupted
EXECUTE histories. Reconciliation never publishes, repairs or retries native output.

An earlier inherited boundary requires an absent intended Content namespace. A changed
previously committed dependency is contradictory evidence and retains ownership. A resumed
attempt with no new stages still inherits its original boundary: it cannot be mistaken for
an original pre-fetch run. Recursive RESUME after reconciliation of a resumed attempt remains
explicitly unsupported; it needs a separate bounded continuation contract. This implementation
retains that run PAUSED and rejects another RESUME rather than losing its prefix.

Copying successful rows would falsify execution history. Inferring ancestry from directories,
timestamps or output counts would substitute evidence. A generic workflow engine would add an
unnecessary execution authority. Reusing the narrow existing readers preserves native identities
at the cost of repeated read-only qualification and a deliberately limited continuation policy.

Content dispatch remains disabled. Up to 32 retained 5 MiB feed payloads exceed the existing
64 MiB private-attempt recovery cap before sidecars. Per-file and per-stage bounds do not
prove an aggregate execution envelope. Increasing the cap alone merely moves the unsupported
boundary; deleting evidence or weakening verification is unacceptable. A separately reviewed
bounded validation/admission design and real API/worker acceptance are still required.
