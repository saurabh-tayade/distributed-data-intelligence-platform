# ADR 0011: Artifact import maintenance ownership

Status: **Accepted — October 21, 2026**

Date: October 21, 2026.

Owner approval: E5 B2b-1A, durable import maintenance ownership only. This decision is additive to [ADR 0010](0010-durable-execution-coordination-and-recovery.md); its run/attempt recovery model and accepted native contracts remain unchanged. Native qualification, a functional importer and B2b-1B remain subject to separate owner review. Architecture acceptance is distinct from implementation and executed test evidence.

## Problem and repository evidence

The B2b-1 request authorizes verified input imports and allows a small compatible forward migration. It also requires stopping for owner review if the accepted coordinator model cannot represent import maintenance ownership safely. Inspection at `b0ffd78eb8e9597d74241c679c2b473facec12ac` found that the documented maintenance slot has no corresponding owner representation or abandoned-import closure protocol in B1/B2a:

| Boundary | B1/B2a contract at inspection and consequence |
| --- | --- |
| [V1 coordinator](../../services/content-api/src/main/resources/db/migration/V1__profiles_and_coordinator.sql) | Modes are READY, STOPPING and RECOVERY_ONLY. `active_attempt_id` and `owner_instance_id` must be null together; an owner references `worker_instances` in the same installation. There is no maintenance/import owner identity |
| [V3 ownership FK](../../services/content-api/src/main/resources/db/migration/V3__runs_attempts_and_stages.sql) | The deferred `(active_attempt_id, owner_instance_id, epoch)` FK must identify an actual attempt. Every attempt requires a run and has kind EXECUTE or RECONCILE. An importer cannot occupy this binding without fabricating execution history |
| [V4 recovery controls](../../services/content-api/src/main/resources/db/migration/V4__controls_rss_and_audit.sql) | RECONCILE requires a run, target attempt and quiescence confirmation. The accepted occupied-slot transfer also requires these records; it cannot close an abandoned import that has no run |
| [V5 coordinator guard](../../services/content-api/src/main/resources/db/migration/V5__immutable_identity_and_version_guards.sql) | Mutable fields are enumerated and versioned. Adding another ownership family requires explicit FK, exclusivity and transition rules, not just setting an otherwise unused UUID |
| [B1 repository](../../services/content-api/src/main/java/platform/contentapi/execution/JdbcCoordinatorRepository.java) | `compareAndSetIdleMode` regards `active_attempt_id IS NULL` as idle, including STOPPING/RECOVERY_ONLY. A second caller with the current version can change that mode; there is no import token to compare or durable import result to resolve |
| [Runtime roles](../../services/content-api/src/main/java/platform/contentapi/execution/RuntimeRole.java) | Only analytics, api, worker and migrate exist. `operator-import` is deliberately rejected; the worker is still idle and has no host guard |

A STOPPING flag could prevent a future well-behaved claim, but does not establish the required durable import identity, conditional finalization, lost-acknowledgment lookup or post-crash closure. A host lock alone can be released while orphan Spark descendants remain. Holding a SQL transaction over verification would violate the accepted short-transaction boundary. Neither approach fulfills B2b-1.

The historical review point was the addition of an independent owner family and its recovery semantics to the normative attempt-only coordinator contract. The owner has now approved its meaning and release authority under the B2b-1A refinements below. Existing V1–V6 must remain unchanged.

## Accepted decision and B2b-1A refinements

The owner approved the correction on October 21, 2026, with the B2b-1A safety refinements below. Use one forward V7 migration with an import-specific ownership record and a mutually exclusive reference from the existing singleton coordinator. Keep the same host guard/global slot, existing three coordinator modes and all run/attempt/control enums. Continue to use only `artifacts` and `artifact_dependencies` for artifact metadata.

1. Add `artifact_import_operations` solely for import intent, ownership and terminal acknowledgment. Required immutable fields: opaque `import_id`, installation UUID, process-instance UUID/PID/start instant, execution-profile ID/digest, host-binding digest, positive owner epoch, operation kind IMPORT/RECOVERY and predecessor link, exact canonical request evidence/hash (at most 64 KiB; B2b-1B must enforce at most 128 explicit catalog selections) and database start time. Mutable fields: ACTIVE/SUCCEEDED/FAILED/INTERRUPTED state, expected row version, terminal time, fixed safe outcome code and exact result bytes/hash (at most 64 KiB). Result bytes identify registered opaque artifact IDs/evidence digests; they are not a second artifact registry. Permit only ACTIVE-to-terminal transitions with version increment; terminal outcomes and immutable identity are sealed against UPDATE/DELETE/TRUNCATE.
2. Add nullable `coordinator.active_import_id`, with a deferred composite FK to `(import_id, installation_id, owner_epoch)`. The active-import pointer is the ownership authority, independently of mode; STOPPING retains its original shutdown meaning and is never a maintenance lock. Acquisition requires READY and leaves mode unchanged. Enforce null execution-attempt/worker-owner fields while import ownership is present. Enforce mutual exclusion with execution/recovery ownership and one ACTIVE import. Retain existing deferred attempt-owner FK unchanged. Extend the V5 coordinator mutable-field guard explicitly for the new pointer. Enforce coordinator/operation state consistency at transaction completion; cross-table checks must serialize on the coordinator, including active attempt/run admission.
3. Extend every idle/claim/mode mutation predicate to require both owner pointers null and no unresolved active run, attempt or import. Extend coordinator snapshots to include the import pointer. Source management can continue its existing short metadata transactions and must never release either owner. Test existing B1 mode primitives against occupied import ownership.
4. Acquire the persistent, identity-checked installation host guard before acquiring import ownership. Under a short coordinator-first transaction, require the correct installation, READY mode, no occupied owner and no unresolved active run/attempt/import; increase epoch, insert ACTIVE intent, bind the pointer and append a safe intent audit. Confirm this commit before any verifier/Spark launch. Do not register a worker attempt or submit a run.
5. Qualify the exact catalog selection outside every SQL transaction. After verification, recheck root, marker, directory, inventory and file evidence. Under a final short coordinator-first transaction, compare import ID, process identity, epoch, coordinator version and operation version/state. Atomically insert/reuse immutable artifacts, insert required native dependency edges, store the terminal result, append safe result audit and clear only this import owner. Preserve coordinator mode and release only when child cleanup is proven. B2b-1A finalization stores internal deterministic coordination results only; native artifact/dependency registration belongs to B2b-1B and must join this final transaction. A conditional mismatch rolls back all registry/result/audit changes and stops the operation.
6. A definite, safely cleaned-up verification failure can atomically record FAILED plus a fixed classification/audit and release this owner. Unknown process cleanup, database failure or uncertain commit acknowledgment never triggers best-effort slot clearing. No native file repair or overwrite occurs.
7. Resolve lost intent/result acknowledgment by reading the exact import ID and canonical request bytes. A committed result is historical evidence; it does not authorize a new verified success without revalidation. A fresh import invocation uses a new operation ID, independently requalifies all inputs, and can reuse only byte-identical registered identities. Never relaunch an ACTIVE operation after a lost acknowledgment.
8. An abandoned ACTIVE import retains its coordinator pointer even after the host lock becomes free. A new recovery owner first acquires the same guard, supplies explicit trusted-operator quiescence confirmation and checks observable old-owner process identity. In one coordinator-first transaction, compare exact old operation/process/epoch/versions, close the old operation INTERRUPTED, insert an ACTIVE RECOVERY successor with the same immutable request/profile/host binding, increment epoch and replace the occupied pointer. Never clear the pointer between owners. Retain the predecessor link and original evidence. Each predecessor has at most one successor; repeated recovery after another crash follows the same fenced protocol. Only a separate safe finalization of the current recovery owner can release the slot. No qualification or publication occurs during handoff/closure.

The owner explicitly requires this occupied-to-occupied recovery handoff instead of the original proposal's direct abandoned-owner release. Database metadata, an expired heartbeat, a released FileChannel lock, process exit or a reused PID cannot prove descendant termination. A live matching owner process or unavailable process identity vetoes handoff; explicit operator confirmation must cover orphan descendants and unmanaged writers that cannot be observed automatically. Unknown acknowledgment is resolved by querying the same operation ID/request, never a fresh blind handoff or automatic takeover. Migration/application code must be delivered together; V1–V6 are unchanged.

## Artifact identity correction in the same checkpoint

V2 already makes `(storage_binding_id, relative_address)` unique and V5 seals artifact/dependency rows. However, `artifacts_native_identity_idx` is nonunique. B2b-1 also needs a database-enforced native identity key, scoped as UNIQUE NULLS NOT DISTINCT `(product_id, kind, contract_version, processor_revision, native_format, native_identity)`. A new native_format column distinguishes JSONL/PARQUET for Reliability batch/publication kinds; other kinds require null. These are namespace scopes, not qualification. V6 has no trustworthy format column: existing Reliability rows therefore fail V7 explicitly with ARTIFACT_NATIVE_FORMAT_UNRESOLVED instead of inferring a format from unqualified strings or manifests. Other scoped duplicates fail ARTIFACT_NATIVE_IDENTITY_CONFLICT. The future fixed importer must define native identity using native namespace keys, with fingerprint/evidence compared separately; changing bytes must not create another native identity. Existing duplicates must abort migration for owner inspection, with no deduplication or rewriting. This constraint is separate from the maintenance-owner decision and does not permit Gold/Content/Reliability publication imports.

## Alternatives and tradeoffs

| Alternative | Assessment |
| --- | --- |
| STOPPING plus host lock, without an import owner | Avoids a table but lacks durable request/owner/result binding and guarded abandoned-import closure; insufficient |
| Fake run/EXECUTE or RECONCILE attempt | Reuses current FKs but invents processing history and violates the B2b-1 boundary; rejected |
| Session/advisory lock or verification-long SQL transaction | Loses exclusion on connection loss or holds a transaction during I/O/Spark; rejected |
| General lease/lock framework or owner polymorphism across all execution records | Broader architectural change than this single maintenance operation; unnecessary |
| Independent import operation referenced by the existing coordinator | Adds one operational table and pointer, explicit crash recovery, migration/readiness work and tests; preserves the single slot and native artifact authority |

This is a correctness/complexity tradeoff, not a performance claim. No dependency or service is proposed beyond B1's PostgreSQL and the existing Python/Spark runtime.

## Acceptance criteria

- B2b-1A: real PostgreSQL proves mutually exclusive attempt/import ownership, conditional version/epoch checks, atomic operation/result/audit commit and rollback, and scoped native/location constraints independently of application checks. Actual registry/dependency registration joins finalization in B2b-1B.
- Two cooperative local owners cannot acquire the guard concurrently; native qualification remains B2b-1B. Occupied execution/recovery/import ownership blocks admission despite expired heartbeat, disconnected DB session or a free host guard.
- Fault injection before qualification, after qualification and around commit leaves either one committed terminal result or the exact unresolved owner; lost acknowledgment never causes blind verifier relaunch or slot clearing.
- Explicit import closure cannot release a changed owner, bypass actual quiescence, use run controls or modify native artifacts.
- B2b-1B only: actual native readers qualify JSONL v2 and Parquet-v1/v2-profile batches, publisher/service snapshots and completed Silver. Full Silver capture supplements the existing Spark schema/provenance boundary without changing its contract.
- B2b-1B only: all requested corruption, missing dependency, changed inventory, unsafe path, idempotency and regression cases in B2b-1 pass before calling that checkpoint implemented. Hosted CI remains unverified until observed after owner publication.

## Current disposition

B2b-1A is implemented and locally coordination-tested: 189 unit/component tests, 106 PostgreSQL tests and 20 HTTP/Python compatibility tests passed. These results do not qualify any native import. The [supporting contract](../architecture/durable-execution.md) and [operational guide](../../services/content-api/README.md) record implementation/evidence separately. The operator-import role remains unavailable for real imports. B2b-1B native qualification/registration, B2b-2 submission and worker execution require separate owner authorization.
